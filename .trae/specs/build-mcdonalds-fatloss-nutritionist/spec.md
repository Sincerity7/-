# 麦门减脂营养师（Maimen Fat-Loss Nutritionist）Spec

## Why

参赛作品需要一个"麦当劳减脂配餐"网页应用：根据用户身体数据与忌口，基于麦当劳官方餐品营养数据自动生成 3 套严格控卡的早+午+晚一日套餐，并提供横向对比与单品查询/替换能力。当前环境无可用麦当劳 MCP 工具，经与用户确认，采用"官方数据内置快照 + 可替换数据层"方案，纯前端 Vue3 SPA 交付。

## What Changes

* 新建 Vue 3 + Vite + Element Plus 单页应用（工作区根目录 `c:\Users\何锐\Desktop\麦当劳`），全部代码使用中文注释。

* 从麦当劳中国官网（mcdonalds.com.cn）抓取真实餐品数据，整理为标准"MCP 返回格式"的 JSON 快照内置到应用中；官网未公开的字段标记为 null 并在界面显示"未公开"，严禁编造数据。

* 新增统一数据服务层 `mcpClient`：当前读取内置快照，接口签名与真实麦当劳 MCP 返回结构对齐，未来拿到 MCP 地址可无缝替换。

* 新增用户信息收集表单（性别、身高、体重、日常活动量、每日热量上限、过敏原/忌口），信息不全时逐项引导补齐，不允许跳过直接配餐。

* 新增营养计算工具（Mifflin-St Jeor 基础代谢 BMR + 活动系数 TDEE），用于给用户展示参考热量值。

* 新增套餐生成器：先按过敏原/忌口过滤餐品，再生成 3 套一日三餐套餐（控卡优先 / 性价比优先 / 饱腹感优先），每套总热量严格控制在用户目标热量 ±5% 内，同等条件下优先高蛋白、低钠。
* 【数据降级决策，已与用户确认】麦当劳中国官网公开网页经核实不披露过敏原清单与单品售价（价格仅在 App/小程序）：过敏原改为"餐品名称关键词 + 官网新闻页官方过敏原提示"推断，每条数据标注推断依据与"非官方声明"；售价字段保持 null，界面显示"官网未公开"，"性价比优先"策略改用代理指标（单位热量蛋白质最高）。

* 新增 Markdown 输出与渲染：每套套餐输出餐品清单（含单品价格/热量/三大营养素/钠）、整套总价、整套总热量、三大营养素汇总；以 markdown 表格 + 分割线形式生成并由前端渲染。

* 新增对比板块：3 套方案横向对比总热量、总蛋白质、总价，并标注各自适合的场景。

* 新增额外指令能力：①指定单品 → 展示该单品完整营养与价格；②不喜欢某单品 → 自动替换为同类型（同分类/同餐段）、热量 ±10% 以内、不含过敏原的麦当劳单品，并实时重算整套汇总。

## Impact

## ADDED Requirements

### Requirement: 餐品数据快照（MCP 格式内置）
系统 SHALL 内置一份来自麦当劳中国官网的真实餐品数据快照，字段包含：餐品名称、分类、可售餐段（早餐/全天）、热量(kcal)、蛋白质(g)、碳水(g)、脂肪(g)、钠(mg)、过敏原列表、售价(元)，并附带数据来源与抓取时间元信息。过敏原 SHALL 由"名称关键词 + 官网新闻页官方过敏原提示"推断填充，并附 `allergenBasis` 推断依据字段；售价因官网不公开保持 null。数据层 SHALL 通过统一接口暴露，便于后续替换为真实麦当劳 MCP。

#### Scenario: 数据真实可溯
- **WHEN** 应用加载餐品数据
- **THEN** 营养数值与价格相关记录均来自官网抓取结果；官网未提供的字段为 null，界面显示"未公开"，不出现任何编造数值；推断过敏原均带有"非官方声明"标注

#### Scenario: 数据层可替换

* **WHEN** 未来接入真实麦当劳 MCP

* **THEN** 仅需替换 `mcpClient` 内部实现，上层生成逻辑与 UI 零改动

### Requirement: 用户信息收集与引导补齐

系统 SHALL 提供表单收集：性别、身高(cm)、体重(kg)、日常活动量（久坐/轻度/中度/重度）、每日热量上限(kcal)、过敏原/忌口（多选：麸质/鸡蛋/牛奶/花生/坚果/大豆/鱼类/甲壳类/猪肉/牛肉等 + 自定义文本）。必填项缺失时 SHALL 阻止生成并逐项高亮提示补齐；同时 SHALL 依据 BMR/TDEE 给用户展示参考热量值辅助填写每日热量上限。

#### Scenario: 信息不全

* **WHEN** 用户未填完必填项即点击"生成套餐"

* **THEN** 系统不生成方案，表单定位到缺失项并给出中文引导提示

#### Scenario: 参考热量

* **WHEN** 用户填完性别/身高/体重/活动量

* **THEN** 表单显示计算出的 BMR 与 TDEE 参考值，供用户设定每日热量上限

### Requirement: 过敏原与忌口过滤

系统 SHALL 在配餐前自动过滤掉命中用户任一过敏原或忌口关键词的餐品。过敏原数据为推断值（名称关键词 + 官网新闻页官方提示），被选用的推断过敏原餐品 SHALL 在结果中显示"过敏原为推断数据，非官方声明"；无法推断的餐品保留并标注"过敏原未知，请自行确认"。忌口自定义关键词 SHALL 同时匹配餐品名称。

#### Scenario: 含过敏原餐品被排除

* **WHEN** 用户勾选"牛奶"过敏

* **THEN** 生成的 3 套方案中不出现任何含牛奶过敏原的餐品

### Requirement: 三套一日套餐生成

系统 SHALL 生成 3 套独立的早+午+晚套餐：控卡优先（总热量最接近目标下限且钠最低）、性价比优先（代理指标：每 100kcal 蛋白质克数最高，因官网不公开售价无法按真实价格计算）、饱腹感优先（蛋白+脂肪+总重量/体积代理最高）。每套总热量 SHALL 落在用户目标热量 ±5% 区间内；每餐由 1 个主食类 + 可选小食/饮品组成，早餐仅从早餐餐段餐品中选取。同等达标条件下 SHALL 优先高蛋白、低钠。

#### Scenario: 热量严格达标

* **WHEN** 用户每日热量上限为 1600 kcal

* **THEN** 3 套方案各自的总热量均在 1520–1680 kcal 区间

#### Scenario: 无解兜底

* **WHEN** 过滤后可用餐品无法满足热量区间

* **THEN** 系统明确提示"当前忌口条件下无法凑出达标套餐"，并建议放宽条件，而不是强行输出超标方案

### Requirement: Markdown 套餐输出

每套方案 SHALL 输出 markdown 内容：餐品清单表格（餐段、名称、单品价格、热量、蛋白质、碳水、脂肪、钠）、分割线、整套总价、整套总热量、三大营养素汇总（蛋白质/碳水/脂肪克数及供能比）。单品价格与整套总价因官网不公开 SHALL 显示"未公开"占位（保留列结构）。前端 SHALL 将该 markdown 渲染为整齐表格展示。

#### Scenario: 输出结构

* **WHEN** 套餐生成完成

* **THEN** 页面以渲染后的 markdown 表格展示清单与汇总，数值与数据快照逐条一致

### Requirement: 三套方案横向对比

系统 SHALL 提供对比板块：一张横向 markdown 表格对比 3 套方案的总热量、总蛋白质、总碳水、总脂肪、总钠、总价（价格列显示"未公开"），每套标注适合场景（控卡优先/性价比优先[蛋白/热量比]/饱腹感优先）。

#### Scenario: 对比呈现

* **WHEN** 3 套方案生成完成

* **THEN** 对比表出现，且各套汇总值与其清单明细合计一致

### Requirement: 额外指令（单品查询 / 不喜欢替换）

系统 SHALL 支持：①按名称搜索任意麦当劳单品并展示其完整营养与价格；②对方案中任一单品点击"不喜欢"，自动替换为同分类/同餐段、热量在 ±10% 以内、不含用户过敏原的其他单品，替换后整套价格、热量、三大营养素与对比表实时重算；③可再次替换或还原。

#### Scenario: 替换保持达标

* **WHEN** 用户将午餐主食替换为另一单品

* **THEN** 新单品与原子品同类型、热量差 ≤10%，且整套总热量仍在目标 ±5% 内，汇总即时更新

## MODIFIED Requirements

无（全新项目）。

## REMOVED Requirements

无。

## 非目标（Out of Scope）

* 不做用户账号体系、不做后端服务、不做真实下单/支付。

* 不实现真实麦当劳 MCP 对接（仅预留可替换数据层）。

* 不做多日食谱循环、购物清单导出等扩展功能。
