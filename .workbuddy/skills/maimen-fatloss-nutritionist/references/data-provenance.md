# 数据口径说明

## 来源

- 采集自麦当劳中国官网 `https://www.mcdonalds.com.cn`（产品页 + 营养信息页）
- 快照时间：2026-10-25
- 官网标注的营养数据更新月份：2025 年 4 月
- 共 91 个单品，覆盖麦咖啡(23) / 早餐(16) / 汉堡和卷(14) / 饮品(12) / 甜品(9) / 开心乐园餐(9) / 小食(8)

## 字段与口径

| 字段 | 说明 | 可靠性 |
|---|---|---|
| `calories` | 官网以 kJ 标注，按 1 kcal = 4.184 kJ 换算取整 | 高，官网原始数据 |
| `protein/carbs/fat/sodium` | 官网原始值，多规格取中杯/中份 | 高，官网原始数据 |
| `mealPeriod` | `breakfast` 仅早餐时段供应，`allDay` 全天 | 高 |
| `allergens` | **推断值**，见下节 | 中 |
| `allergenBasis` | 推断依据的明文说明 | — |
| `price` | **全部为 null**：官网公开页不披露售价，仅 App/小程序可见 | 无 |
| `unit` | 规格，如"1个""中""2块" | 高 |

## 两个必须对用户讲清楚的点

### 1. 价格：不做估算

官网公开页没有价格，所以 `price` 全是 `null`，界面与输出统一显示"未公开"。**不要**用"一般 20 块左右"这类话术填补，也不要按品类给估值——参赛演示里一旦被追问来源就站不住。

如果之后拿到门店实际售价，直接在 JSON 里填 `price` 即可，脚本会自动计算整套总价（任一单品缺价则整套仍显示"未公开"，避免半吊子汇总）。

### 2. 过敏原：推断，非官方声明

官网产品页不披露过敏原清单。当前 `allergens` 是三类依据叠加的保守推断：

1. **名称关键词**：如"麦香鱼"含"鱼"→鱼类；"吉士汉堡"含奶酪→牛奶
2. **配方常识**：汉堡/卷/麦满分的面包胚→麸质；油炸裹粉→麸质
3. **官网新闻页的官方过敏原提示**（如有）

覆盖率 63/91，未覆盖的 28 条保持 `null`，脚本会打 `allergenUnknown` 标记，输出中提示"过敏原未知，请自行确认"。

**凡是选用了推断过敏原的单品，结果里必须保留"非官方声明"这句提示。** 严重过敏的用户应直接向门店确认，这一点要主动讲。

## 一个已验证的事实

麦当劳早餐的堡 / 卷 / 麦满分**全部含麸质**，午晚餐的汉堡与卷也全部含麸质。因此：

- 麸质过敏 → 早餐无堡类可选，脚本自动降级为粥类/小食组合并给出提示
- 麸质过敏同时还要午晚餐 → 在麦当劳内无解，脚本会明确报错并指出是哪条忌口卡住的

这是真实约束，不是程序缺陷。遇到时如实说明，不要放宽条件硬凑。

## 替换数据源

拿到真实麦当劳 MCP 后，只要产出同样结构的 `{meta, items}` JSON：

```bash
python scripts/maimen.py plans --data /path/to/live-menu.json --sex 男 --height 175 --weight 70 --target 1600
# 或
MAIMEN_MENU=/path/to/live-menu.json python scripts/maimen.py stats
```

脚本、输出格式、套餐逻辑都无需改动。
